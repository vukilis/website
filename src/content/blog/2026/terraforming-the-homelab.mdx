I run most of my homelab services as LXC containers on Proxmox. To avoid clicking through the Proxmox UI every time I want to add or change something, I moved the whole setup into Terraform. Here is how it's structured.

## Architecture

The config follows a two-layer pattern:

- **Live** - each environment has its own configuration with the values needed to set up the modules
- **Modules** - reusable blueprints that define *how* to create a resource

There are two independent live environments:

- `live/containers/` - manages all LXC containers
- `live/vms/` - manages all QEMU VMs

Each maintains its own state file and can be applied independently.

## Directory Structure

```bash
terraform/
└── proxmox/
    ├── live/                    # Implementation Layer (Environments)
        └── containers/
            ├── main.tf          # Calls the module and defines specific container instances
            ├── outputs.tf       # Displays final container IDs and IPs after deployment
            ├── provider.tf      # Proxmox API connection settings
            └── variables.tf     # Environment-specific variable definitions
        └── vms/
            ├── main.tf          # Calls the module and defines specific VM instances
            ├── outputs.tf       # Displays final VM IDs and IPs after deployment
            ├── provider.tf      # Proxmox API connection settings
            └── variables.tf     # Environment-specific variable definitions
    ├── modules/                 # Blueprint Layer (Reusable Code)
        └── proxmox_lxc/
            ├── main.tf          # The core resource logic for "proxmox_lxc"
            ├── outputs.tf       # Attributes exported from the module to the live layer
            └── variables.tf     # The required inputs (RAM, CPU, Disk) for the module
        └── proxmox_vms/
            ├── main.tf          # The core resource logic for "proxmox_vms"
            ├── outputs.tf       # Attributes exported from the module to the live layer
            └── variables.tf     # The required inputs (RAM, CPU, Disk) for the module
```

## Provider

**`Telmate/proxmox` v3.0.2-rc07** - a community provider for Proxmox VE. It manages both LXC containers (`proxmox_lxc`) and QEMU VMs (`proxmox_vm_qemu`). TLS verification is disabled (`pm_tls_insecure = true`) since Proxmox uses a self-signed certificate in the homelab.

## Modules

Terraform blueprints that define how to provision LXC containers and QEMU VMs on Proxmox.

### LXC Module

The `proxmox_lxc` module creates and manages LXC containers using the `telmate/proxmox` provider.

Key provisioning behaviors:

- SSH hardening via `null_resource` provisioners that SSH into the Proxmox node and set `PermitRootLogin prohibit-password`
- Alpine-specific hardening that also installs `openssh` via `apk add` before configuring SSH
- Randomized `sleep` based on VMID to prevent SSH connection collisions during parallel creation

```ini frame="terminal"
terraform {
    required_providers {
            proxmox = {
            source  = "telmate/proxmox"
            version = "3.0.2-rc07"
        }
    }
}

resource "proxmox_lxc" "container" {
    ssh_public_keys = var.ssh_public_keys

    target_node  = var.target_node
    ostemplate   = var.ostemplate
    start        = var.start_at_boot

    vmid         = var.vmid
    password     = var.root_password
    unprivileged = var.unprivileged

    # Resource Allocation
    cores        = var.cores
    cpulimit     = var.cpu_limit 
    cpuunits     = var.cpu_units
    memory       = var.memory
    swap         = var.swap      

    rootfs {
        storage = var.storage
        size    = var.disk_size
    }

    # Network Settings
    network {
        name   = var.network_name
        bridge = var.network_bridge
        ip     = var.ip_address
        gw     = var.gateway
    }

    # Identity & DNS
    hostname     = var.hostname
    searchdomain = var.searchdomain
    nameserver   = var.nameserver
    tags         = join(";", var.tags)

    # Other Settings
    onboot = var.onboot

    features {
        nesting = var.nesting
        keyctl  = var.keyctl
    }
}

resource "null_resource" "ssh_config_provisioner" {
    count = var.enable_ssh_hardening ? 1 : 0

    triggers = {
        container_vmid = proxmox_lxc.container.vmid
    }
    provisioner "local-exec" {
        command = <<EOT
            sleep $(( ( ${proxmox_lxc.container.vmid} % 5 ) + 1 ))

            ssh -o StrictHostKeyChecking=no \
                -o UserKnownHostsFile=/dev/null \
                -o IdentitiesOnly=yes \
                -o ConnectTimeout=10 \
                -i "~/.ssh/vukilis" root@${var.pve_connection} \
                "pct exec ${proxmox_lxc.container.vmid} -- sed -i 's/^#*PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config && \
                pct exec ${proxmox_lxc.container.vmid} -- systemctl restart ssh"
        EOT
    }
}

resource "null_resource" "alpine_ssh" {
    count = var.alpine_ssh_hardening ? 1 : 0

    triggers = {
        container_vmid = proxmox_lxc.container.vmid
    }
    provisioner "local-exec" {
        command = <<EOT
            # Random sleep to prevent SSH collisions during bulk creation
            sleep $(( ( ${proxmox_lxc.container.vmid} % 5 ) + 1 ))

            ssh -o StrictHostKeyChecking=no \
                -o UserKnownHostsFile=/dev/null \
                -o IdentitiesOnly=yes \
                -o ConnectTimeout=10 \
                -i "~/.ssh/vukilis" root@${var.pve_connection} \
                "pct exec ${proxmox_lxc.container.vmid} -- apk add --no-cache openssh && \
                pct exec ${proxmox_lxc.container.vmid} -- sed -i 's/^#*PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config && \
                pct exec ${proxmox_lxc.container.vmid} -- rc-update add sshd default && \
                pct exec ${proxmox_lxc.container.vmid} -- rc-service sshd restart"
        EOT
    }
}
```
### VM Module

The `proxmox_vms` module creates QEMU VMs by cloning a pre-existing Proxmox template. It uses `full_clone = true` for reliability, linked clones break if the template is modified or deleted.

```ini frame="terminal"
terraform {
    required_providers {
            proxmox = {
            source  = "telmate/proxmox"
            version = "3.0.2-rc07"
        }
    }
}

resource "proxmox_vm_qemu" "virtual_machine" {
    name        = var.hostname
    target_node = var.target_node
    vmid        = var.vmid
    description = var.description              
    vm_state    = var.vm_state
    boot        = var.boot

    # OS Settings
    clone      = var.source_template
    full_clone = true

    # Resource Allocation
    cpu {
        sockets = var.sockets
        cores   = var.cores
        type    = var.type     
        numa    = var.numa  
        units   = var.cpu_units
        limit   = var.cpu_limit
    }
    memory  = var.memory
    scsihw  = var.scsihw

    # Disk Settings
    disks {
        scsi {
            scsi0 { 
                disk {
                    size     = var.disk_size
                    storage  = var.storage
                    discard  = true
                    iothread = true 
                }
            }
        }

        ide {
            ide2 {
                cloudinit {
                        storage = var.storage
                    }
                }
            }
    }

    # Network Settings
    network {
        id = 0
        model  = var.model_type
        bridge = var.network_bridge
    }

    # Cloud-Init & Identity
    os_type                 = "cloud-init"
    ipconfig0               = "ip=${var.ip_address},gw=${var.gateway}"
    nameserver              = var.nameserver
    searchdomain            = var.searchdomain
    sshkeys                 = var.ssh_public_keys
    ciuser                  = var.ci_user
    cipassword              = var.root_password

    # Additional Settings
    hotplug                 = "disk,network,usb"
    start_at_node_boot      = var.start_at_node_boot
    agent                   = 1

    tags = join(";", var.tags)
}
```

## Remote State

Both environments use remote state stored in a Cloudflare R2 bucket. This means:

- State is centralized, not local
- I can run Terraform from any machine with the right secrets
- State locking is handled by the S3-compatible backend

Secrets live in `secrets.auto.tfvars` files (git-ignored, auto-loaded by Terraform). Sensitive variables are marked with `sensitive = true`.

- Auto-start on Proxmox boot

#### Key Design Decisions

1. **Separate live environments** - containers and VMs are managed independently. Changing container configs doesn't require planning VM changes and vice versa.

2. **Provisioner-based SSH hardening** - instead of Cloud-Init scripts (which can be fragile), the module uses `null_resource` provisioners that SSH directly into the Proxmox node after container creation.

3. **Alpine special-casing** - Alpine doesn't ship with SSH by default, so a dedicated `alpine_ssh_hardening` flag handles OpenSSH installation via `apk`.

4. **Full clones for VMs** - `full_clone = true` ensures VMs are independent copies, avoiding the template-deletion problem that breaks linked clones.

5. **Docker-in-LXC** - `nesting = true` and `keyctl = true` enable nested virtualization and kernel keyring access for containers running Docker.

### The VMs Fleet

The VMs environment is currently simpler, it defines a single test VM used for experimentation and validation. Unlike the containers, which run services directly. It's an isolated environment for testing new setups, updates, and practicing break-fix recovery scenarios without any risk to production.

Day-to-day commands for initializing, planning, applying, and maintaining the infrastructure.

```bash
# Initialize locally Cloudflare R2 API
export AWS_ACCESS_KEY_ID=""  
export AWS_SECRET_ACCESS_KEY=""

# Initialize
cd terraform/proxmox/live/containers
terraform init

# Plan changes
terraform plan -target=module.test-container-0

# Apply changes
terraform apply -target=module.test-container-0

# Destroy a specific container
terraform destroy -target=module.test-container-0

# Format code
terraform fmt -recursive
terraform validate
```
